# 仿真与显示契约（当前基线）

## 单位和坐标

- `src/physics/constants.js` 中 `SCENE_UNITS_PER_AU = 250`；行星和飞船的世界位置使用场景距离单位，时间步使用仿真秒。`G` 和质量是项目的缩放数值，不是 SI 制。
- 卫星 `relPos`、`relVel` 是母星相对、轨道平面坐标；`publishWorld` 将它们旋转并加到母星的世界位置和速度。卫星 `muEff = (speed * SCRIPTED_TIME_SCALE)^2 * orbitR^3` 是为了原有周期校准的参数，不应直接当作 `G * mass`。
- 行星 `pos` / `vel` 和卫星 `pos` / `vel` 是仿真状态；Three.js 场景节点是显示状态。

## 显示比例

- 卫星的 `updateScale` 只调整 mesh、轨道线及显示位置的映射，不改变 `relPos`、`relVel`、`orbitR` 或 `muEff`。关闭真实比例后显示位置应回到仿真轨道位置。
- `setOrbitRadius` 是显式修改卫星仿真轨道的操作，而不是比例切换接口。
- 行星和太阳的显示比例仍由各自 `updateScale` 管理；飞船碰撞、驻留和自动驾驶捕获通过 `flightInteractionRadius` 读取 mesh 显示半径，因此切换比例会改变这些交互范围。该函数明确保留原有游戏规则，并非真实物理半径。全局显示与仿真的彻底分离尚未完成，不能直接替换这些半径而不先明确真实比例下的飞行体验。

## 纹理资源

同一纹理请求共享加载；每个材质只接受当前请求的版本。销毁天体或替换恒星材质前撤销关联的未完成请求，过期且无人使用的结果直接释放。缓存按最近使用顺序淘汰未被引用的贴图，并跳过正在使用的贴图继续检查后续条目。上限按条目数而不是显存字节数管理：当存活材质引用的贴图超过上限时，缓存允许超限，不会销毁正在使用的纹理。

## 高倍速与时间

物理引擎会切片并限制每帧积分工作；日期同步会清除旧状态遗留的待处理步骤。可通过 `window.__sim.physicsEngine.getTimingStats()` 检查累计请求、已积分、已丢弃和当前待处理的仿真秒数及待处理步数。其他实时控制和视觉系统目前仍可能使用本帧请求的仿真时间，而不是实际完成积分的时间；在持续高倍速积压时，它们可能与物理轨道不同步。队列丢弃和有效倍率也尚未向用户显示。完整统一需要把控制与物理更新迁入同一个受预算约束的仿真步，并以真实集成时间驱动相关系统。

## 限制

真实比例下卫星显示位置和其仿真世界坐标有意不同。当前自动驾驶目的地从 `physicsEngine.activePlanets` 选取，不含卫星；飞船引力和碰撞循环也处理行星而非卫星。相机聚焦读取 mesh 世界位置。未来若支持飞船导航或碰撞卫星，必须明确映射而不能直接混用 `pos` 和 mesh 坐标。聚焦阴影范围以卫星原始轨道半径计算，是对正常和真实比例显示范围的保守上界。全局其他坐标消费者仍需审计，不能宣称整个应用已完成分离。引力扰动也尚未实现。
